# trioxide

A TypeScript-aware optimising compiler on oxc: per function, optimised JS or Rust→WASM.
`docs/PLAN.md` is the spec; `docs/sessions/` holds the per-session prompts and
`docs/sessions/common.md` the rules every session follows.

## Commands

Run all of these before every push; CI runs the same.

```sh
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
pnpm install && pnpm --filter trioxide build   # napi binding, needed by pnpm tests
pnpm -r test                                   # npm package tests + differential suite
```

Also useful:

- `cargo run -p trioxide_cli -- transform tests/fixtures/classes/input.ts`
- `cargo insta review` after changing output; snapshots live next to each fixture as
  `tests/fixtures/<case>/output.snap`.
- `TRIOXIDE_UPDATE_SCHEMA=1 cargo test -p trioxide schema` regenerates
  `schema/trioxide.schema.json` after changing `Options`; then `pnpm --filter trioxide generate`
  regenerates `packages/trioxide/src/options.d.ts` and `schema.json` (a test checks both).
- Browser tests (plugin HMR, `examples/dom-app`) use Playwright's Chromium if installed, else
  `CHROMIUM_PATH` or a system Chrome. Never run `playwright install`.
- `cargo run -p trioxide_cli -- check-toolchain` reports what WASM islands need.
- `trioxide explain [file[:fn]] [--entry <file>] [--json]` prints the partitioner's verdicts
  (with failed eligibility rules and cost-model numbers) and the passes' decisions.
- `node benchmarks/partition/run.mjs` times kernels JS vs WASM and compares the cost model's
  picks; `fit.mjs` refits its weights, `reach.mjs` reports what qualifies without
  `trustTypes`. `TRIOXIDE_EVERY_CLUSTER=1` makes the differential suite's auto leg turn every
  eligible cluster into an island.
- `FIXTURE=enums pnpm --filter trioxide-differential test` runs one differential fixture.
  `TRIOXIDE_BIN=…` skips the cargo build it otherwise does first.
- `cargo check -p trioxide_cli --no-default-features` builds without tsrs.
- `FIXTURE=islands/nbody pnpm --filter trioxide-differential test` runs one hand-written
  island through all legs, including JS+WASM. Islands are cached in
  `tests/differential/.out/.cache`; `docs/ABI.md` is the island contract.
- `cargo test -p trioxide_rust --test generated` snapshots the Rust generated for
  `tests/islands/*/wasm/` and `tests/wasm/*/` (`generated.snap`) and the diagnostics of
  `tests/wasm-errors/*/`. `trioxide transform --emit=rust <file>` prints the generated crates.
- `RANDOM_SEED=… RANDOM_PROGRAMS=5000 pnpm --filter trioxide-differential test` runs a longer
  random-program sweep of the Rust backend (500 programs, fixed seed, by default).
- `node crates/trioxide_rt/tests/golden/generate.mjs` regenerates the runtime's golden
  tables from V8.
- The first build compiles tsrs (a few minutes). Dependencies are built at `opt-level = 2`
  even in dev because tsrs is very slow unoptimised.

## Conventions

- Rust 2024, workspace lints (`clippy::pedantic` plus a few restriction lints). Every public
  item has a doc comment; internal comments stay sparse. Prefer `#[expect(lint, reason = …)]`
  over `allow`.
- Problems in user code are `trioxide_common::Diagnostic`s on outputs, never `Err`. `Err` is
  for I/O, bad config and unreadable entries.
- Spans are UTF-8 byte offsets; ids are global via `ModuleId` + oxc `NodeId`/`SymbolId`
  (`NodeRef`, `SymbolRef`).
- Every fact has a trust level. Semantics-changing rewrites need `Facts::is_usable`; when a
  rewrite is skipped, log why (`ModuleLog::skipped`) for `explain`. Never guess.
- Tests come with code: an insta fixture for output changes, and a differential fixture
  (a deterministic `export function main()`) for anything that can change runtime
  behaviour. Fixtures import siblings with `.js` specifiers.
- Fixtures without their own `tsconfig.json` use `tests/fixtures/tsconfig.json`.
- `packages/trioxide/binding/index.{cjs,d.cts}` are generated by `napi build` and committed;
  CI fails if they are stale.

## Pins

- All `oxc_*` crates from the oxc monorepo: exactly `=0.154.0`, bumped together in a
  dedicated PR. `oxc_resolver` and `oxc_sourcemap` are versioned separately and also pinned
  exactly (`oxc_sourcemap` must match what `oxc_codegen` uses).
- tsrs: a git dependency pinned by `rev` in the root `Cargo.toml`. Only
  `crates/trioxide_types` may depend on it, behind its default-on `tsrs` feature. tsrs pins
  `unicode-id-start =1.1.2`, which oxc then shares.
- Rust 1.99.1 (tsrs's MSRV) in `rust-toolchain.toml`, with `wasm32-unknown-unknown`.
- Don't bump any pin unless your session prompt says so.

## Crate ownership

Read anything; change only what your stream owns. Cross-stream interface changes must be
minimal, additive, and listed under "Cross-stream changes" in the PR.

| Stream | Owns |
|--------|------|
| S1 Foundation | workspace, CI, `trioxide` facade, `trioxide_common`, `trioxide_project`, `tests/` harnesses |
| S2 Types + analysis | `trioxide_types`, `trioxide_analysis`, `tests/fixtures/analysis/` |
| S3 Vite, npm, CLI | `packages/trioxide` (beyond the loader), `trioxide/vite`, npm platform packages, `trioxide_napi` (additive), CLI ergonomics in `trioxide_cli`, release workflows, `examples/dom-app` |
| S4 / S5 JS passes | passes in `trioxide_js` |
| S6 Rust backend | `trioxide_rust` |
| S7 WASM runtime | `trioxide_rt`, `trioxide_wasm`, `tests/islands/`, the JS+WASM differential leg |
| S8 Partitioner | `trioxide_partition`, `explain` |

Sessions and waves are listed in `docs/sessions/README.md`.

## Where things plug in

- Types: implement `trioxide_types::TypeOracle` (tsrs adapter in `tsrs_adapter.rs`) and set
  it in `Project::new` (`crates/trioxide/src/project.rs`).
- Analysis: `trioxide_analysis::analyze` fills `Facts`; the facade calls it in
  `Project::analyse`.
- Passes: implement `trioxide_js::Pass`, register in `PassManager::from_options`.
- Partitioning: `trioxide_partition::Partitioner::partition`.
- Islands: `trioxide_wasm::IslandSource` (an `IslandSpec` plus Rust files, shaped as
  `docs/ABI.md` says) built by an `IslandBuilder`; results go in `BuildOutput.islands`.
  Hand-written islands live in `tests/islands/<case>/island/`.
